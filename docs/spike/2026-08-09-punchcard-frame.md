# SPIKE · 펀치카드 프레임이 이 파이프라인에 적용되는가

**질문**: 버핏의 20칸 펀치카드를 이 도구 스위트에 반영할 것이 있는가. 있다면 무엇인가.
**시간 상자**: 한 세션
**판정**: **부분 채택** — 4개 교훈 중 2개를 코드로, 1개를 문서로, 1개를 기각

---

## 검토한 것

원 프레임은 네 가지를 주장했다.

1. 인적자본(반도체 커리어)이 이미 1칸을 차지하므로 신규 후보 평가의 첫 질문은
   "이미 뚫린 칸과 다른 칸인가"여야 한다
2. 연구 대기열이 펀치 예산보다 길다 — 기각률이 8~9/10이어야 정상
3. 기각 기록이 매수 기록보다 중요하다
4. '1칸'의 정의를 명문화해야 한다

## 알아낸 것

**1·2·3은 별개가 아니라 한 기능의 세 면이다.**
①은 기각 사유 코드 하나(`factor`)로 환원된다. ②의 기각률은 ③의 원장이 있으면 자동으로
나오는 파생 통계다. 즉 실행체는 ③ 하나뿐이다.

**④는 코드가 아니라 문서다.** 정의표를 PRD에 넣으면 끝난다.

**칸 카운터 UI는 기각.** 원 프레임 스스로 "자금이 계속 유입되므로 20칸이 안 맞는다"고
인정한다. 20이라는 숫자를 UI에 박으면 **이미 기각된 전제를 코드에 고정**하는 셈이다.
추적할 것은 칸 개수(count)가 아니라 칸의 중복도(overlap)다. → ADR D17

**설계상 가장 어려웠던 지점**: 팩터 중복은 종목 단위가 아니라 포트폴리오 단위 질문인데,
포트폴리오 데이터는 파이프라인 끝(TOOL 04)에 있고 필터는 맨 앞에 있어야 한다.
게다가 인적자본 칸은 어느 도구에도 없다. P2(도구별 키 분리)가 앞단에서 뒷단 데이터 접근을
막는다. → 자동 판정을 포기하고 사유 코드 하나로 환원해 해결. 판단은 사람이 한다.

## 검증한 전제

- `holdings`의 `id`가 `Date.now().toString(36)` — 생성 시각 역산 가능.
  덕분에 새 필드 없이 "도입 이후 편입"만 기각률 분모에 넣을 수 있었다
- 기존 원장은 자유 삭제 가능하다. PRD §4.4의 "삭제 후 재입력 불가" 서술은
  코드와 어긋난 드리프트였다 → PRD §8에 기록

## 이 프레임의 기각 조건

도입 3년 시점(2029-08)에 다음 중 하나면 이 기능은 규율이 아니라 사후 서사다.

- 기각 건 0
- 기각률 50% 미만 (필터가 아니라 정당화 장치로 작동)
- 검토중 항목이 전부 결론 없이 1년 이상 방치
- 3년 검증 완료 0 (피드백 루프 미작동)

→ PRD §9 백로그에 점검 항목으로 등록됨
