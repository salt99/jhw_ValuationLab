### 무엇이 바뀌었나

`kellyOf()`는 원장을 보지 않는다. 그래서 전량 청산해도 상단·하단·승률을 안 고치면
켈리가 양수로 남고, 보유 0주인 칸이 계속 매수 목표를 받았다. 게다가 `posSum`에 끼어
**살아있는 종목의 배분까지 희석했다** — 표시가 아니라 숫자가 틀린 문제였다.
실측: 남은 종목 목표비중 `0.372340` → `0.500000`.

- 칸 회수 등재된 종목은 `livePlanHoldings()`가 걸러내 **목표 배분·매매일지 양쪽에서 사라진다**
- 매매 이력은 `▸ 칸 회수` 카드의 `매매 이력` 버튼(읽기 전용 모달)에서 본다
- 칸 회수 모달은 **트리거를 적어야 닫힌다** (닫기 ✕ 숨김, 배경클릭 차단)
- 등재를 건너뛴 기존 데이터는 자동 변환하지 않고 일지에 `칸 회수 미등재` 배너로 유도
- 진행 바가 순매수 음수일 때 100%로 꽉 차던 버그도 고쳤다

## 알아야 할 것

- **폰 백업을 아직 안 받았을 수 있다.** 푸시 전에 받아두는 게 안전하다.
- `test_pipeline.js`가 `compute()`도 검증한다. PURE 블록 밖이라 중괄호 균형으로
  선언만 잘라내는 `grab()`을 쓴다. `compute`·`kellyOf`·`livePlanHoldings`의
  **선언 형태를 바꾸면 이 추출이 깨진다.**
- 배분 검증의 단언은 **"커진다"가 아니라 "줄지 않는다"**여야 한다.
  `posSum < 1`이면 `rel` 증가와 `equityScale` 감소가 정확히 상쇄되어 목표가 안 변한다.
  "항상 커진다"로 짜면 멀쩡한 코드를 버그로 잡는다.
- 자체 검사 스크립트가 `holdings`를 백업하지 않던 것도 고쳤다(`selfcheck-rejection-ledger.js`).

## 손대지 말 것

- **청산 종목의 매매 이력 모달을 수정 가능하게 만들지 말 것.** 읽기 전용이 의도다.
  사용자가 "오타 수정은 무시하고 진행"이라고 명시적으로 판단했다. 대가는 PRD §7-D18에
  적혀 있다 — 청산 후에는 백업 JSON 편집으로만 고칠 수 있다.
- **`holdings[]`에서 청산 종목을 삭제하지 말 것.** 계획에서만 뺀다. 회고용 원장이
  사라지고 `candidates` 스키마에는 원장을 담을 자리가 없다 (§7-D18 기각한 대안 ②).
- `todayStr()` 의 UTC 기준 (`index_kelly.html`). 파일 내 5곳과 같은 관행이고,
  신규 코드만 로컬 시간으로 바꾸면 일수 계산이 음수가 되어 더 나빠진다. 판단 근거는 PRD §8.
- 커밋 `08ecddc` `6216f9b` `668a7cb` 의 제목 50자 초과. 사용자가 유지하기로 결정했다.

## 되돌리는 법

**아직 푸시 안 했으므로** 로컬에서 지우면 끝이다:

```sh
git reset --hard origin/main     # 로컬 6커밋 폐기
```

이미 푸시한 뒤라면:

```sh
git revert --no-commit 632dc07..HEAD && git commit -m "revert: roll back liquidated holding exclusion" && git push
```

→ 10분 내 폰 반영. **저장 포맷을 바꾸지 않았으므로 데이터 손실이 없다.**
