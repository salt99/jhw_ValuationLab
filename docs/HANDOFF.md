### 2. TSMC 문서 3분할 (분석 repo `63b7abc`)

```
docs/analysis/tsmc/
├── tsmc-스터디.md    408줄  v1.0   CH.01–CH.05 + 용어 정리 5개
```

**자르는 기준은 원래 목차(본문/부록)가 아니라 "이해인가 판단인가"다.** 그래서 `CH.06 리스크`

기각 조건으로 끌어다 쓰므로, 적정가와 한 파일에 있어야 매수 판단이 한자리에서 끝난다.
분석 문서에서는 번호를 떼고 `## 리스크와 약점 — 3층 구조` 가 됐다.

**부록 이름 `APP.A`~`APP.F` 는 그대로 뒀다.** 본문 4곳이 `APP.B~E` 를 참조해서 개명하면
연쇄로 깨진다.

**본문은 재배치만 했다.** 커밋본 `23271e7` 의 본문 725줄과 diff 해서 상호참조 9줄 외에
변경이 없음을 확인했다. 미결 큐·개정 이력도 바이트 단위로 원문과 대조했다.

**버전은 문서별로 독립해서 오른다** — MAJOR = 적정가·판정·기각 조건이 움직임, MINOR = 그 외.
규칙은 `tsmc-히스토리.md` 안에 적혀 있다. 묶지 않은 이유: 스터디(산업 이해)는 좀처럼 안
바뀌고 분석(밸류에이션)은 분기마다 바뀌어서, 묶으면 스터디 버전이 거짓말을 한다.

  간 상관관계를 무시하고 각 종목 `f` 를 따로 풀어 정규화하는 것 자체가 휴리스틱이라

  켈리가 못 보는 것(왼쪽 꼬리·상관관계)을 상쇄하는 것**이고, 그렇다면 잘라낸 초과분을 역시
  켈리로 추정된 다른 종목에 넘기는 건 과대평가를 옮기기만 하는 셈이다. 이게 채권으로
  보내기로 한 이유다. 되돌리려는 다음 세션은 이 문단을 먼저 읽을 것.

- **채권이 0% 가 되면 8분기 분할매수의 "매수 대기 실탄"이 사라진다.** 상한 덕에 종목이
  4개 미만이면 채권이 남지만, 4종목 이상에서 켈리가 고르면 채권 0% 가 된다.

- **종목마다 시나리오 도달 기간 관점을 맞춰야 `f` 비교가 유효하다.** 도구는 기간을 묻지
  않는다 — 3년 관점 종목과 15년 관점 종목을 같은 `posSum` 에 넣으면 상대 배분이 왜곡된다.
  연율화하지 않는 것도 의도다. **풀 켈리로 바뀌면서 이 왜곡의 대가가 2배가 됐다.**

- **입력 레이아웃이 스펙 목업과 다르게 렌더된다.** `.prob-in{width:64px}` 가
  `.fld input{width:100%}` 에 밀려(특정성 0,1,0 vs 0,1,1) 목표가·확률이 나란히가 아니라
  **위아래로 쌓인 동일 너비 입력 두 칸**으로 나온다. 사용자가 폰에서 보고 "이상없음"
  했으므로 실사용상 문제는 없다고 판단됐다.

- **`readProb()` 는 호출처 0인 죽은 코드다**(`:1012`). 기존 코드라 삭제하지 않았다
  (CLAUDE.md §3). 지울 거면 별도 커밋으로. `readProbs()`(`:1016`)가 실제로 쓰이는 쪽이다.

- **`test_pipeline.js:252, 380, 386` 의 `f = p/a − q/b` 는 stale 이 아니다.** 3-시나리오를
  2-결과로 축퇴시켰을 때 옛 공식과 일치하는지 검증하는 앵커다(§7-D20 축퇴 성질).

## 되돌리는 법

### 이번 세션 되돌리기

**부모 저장소는 이 HANDOFF 커밋 하나뿐이다.** 도구 코드·`.gitignore` 무변경.

분석 저장소(`docs/analysis` 안에서):

- `git revert 307add9` — 검증 스크립트를 되돌린다
- `git revert 8944627` — 템플릿 4파일을 되돌린다. **아직 아무 종목도 이걸 안 쓰므로
  부수 피해가 없다** (TSMC 재작성 전이다)

### 지난 세션(저장소 분리) 되돌리기

- `git revert 73a6040` — 참조·규약 갱신만 되돌린다
- `git revert 63b7abc` — 3분할을 되돌려 `기업분석.md` 748줄로 복귀
- **원본만 꺼내보려면** `git show 23271e7:tsmc/기업분석.md`
- `git log -M30% --follow --stat -- tsmc/tsmc-분석.md` — 기본 임계값(50%)에서는 rename
  으로 안 잡힌다. 분할 후 유사도가 362/748 = 48% 라 문턱을 못 넘는다

### 직전 세션(도구) 되돌리기 — 데이터 안전

표시 문자열만 바꿨다. 저장 형식도 계산도 그대로다.

- `git revert d523106` — "상방 없음" 문구가 사라지고 옛 `'시나리오가 퇴화했습니다'` 로
  돌아간다. `test_pipeline.js` 의 err 경로 2건도 함께 되돌아간다(131 → 129)
- `git revert 1ab996d` — 목표 포트폴리오·매매일지에서 Base 와 확률이 다시 안 보인다

### 사이징 변경 되돌리기 — 데이터 안전

- 상한만: `git revert 5079bfa` — 40% 재분배 방식으로 돌아간다(2종목 구멍도 함께)
- 풀 켈리까지: `git revert 5079bfa 84d0a9b` — 하프 켈리·40% 재분배로 완전 복귀
- **상한 수치만 바꾸고 싶으면** `MAX_SINGLE`(`:929`) 한 줄이다. 다만 `test_pipeline.js` 의
  `상한 —` 세 그룹이 0.30 을 상수로 박아두었으므로 함께 고쳐야 한다. 그게 의도다.

### ⚠ 3-시나리오까지 되돌리기 — 데이터가 안전하지 않다

**`prob` 필드의 의미가 바뀌었다.** v4에서는 "승률"(나머지 1−p가 전부 하단)이고, v5에서는
"P(Bull)"(나머지가 Base와 Bear로 나뉜다). 필드 이름과 타입이 같아서 옛 빌드가 **에러 없이
읽고 조용히 다르게 해석한다.**

실측 — 현재가 100 · Bull 150(25%) · Base 120(50%) · Bear 70(25%) 종목:

| 빌드 | f | 결과 |
|---|---|---|
| 새(3-시나리오) | **1.6085** | 배분에 포함 |
| 옛(같은 데이터) | **−0.6667** | **음수 켈리로 배분에서 제외** |

종목이 계획에서 통째로 사라지는데 경고가 없다. 되돌리려면 순서가 있다:

1. 폰에서 `⬇ 내보내기`로 v5 백업을 받아둔다
2. 코드를 revert 해서 배포한다
3. **v5 이전 백업으로 `⬆ 가져오기`** 하거나, 각 종목의 `prob` 을 옛 의미(승률)로 손으로
   고친다. 안 하면 종목들이 배분에서 사라진 채로 남는다

계산 수준의 롤백은 `kelly3` 에 `p_base=0, r_base=0` 을 넘기면 정확히 같은 값이 나온다 —
축퇴 성질이 그 경로를 겸한다(PRD §7-D20).

**교훈**(§7-D21): 필드를 **추가**하는 것과 기존 필드의 **의미**를 바꾸는 것은 다르다.
후자는 스냅샷 버전만으로 방어되지 않는다 — 옛 빌드는 버전을 보고 거부하지 않고 그냥 읽는다.
