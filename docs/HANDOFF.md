### 1. 화면 표시 — `scenLine()` 도입 (커밋됨)

두 줄이 각자 문자열을 조립하고 있어 표기가 어긋나 있었다(목표 포트폴리오는 `p=55%`,
매매일지는 하단만). `scenLine(h)`(`index_kelly.html:1043`) 하나로 합치고 압축했다.

```
전  $264 → ▲300 / ▼200 · p=55% · $      30자, 값 3개
후  $264 ▲300 ◆280 ▼200 · 55/25/20      30자, 값 6개
```

화살표·괄호·`%`·끝의 중복 통화기호를 빼서 **폭은 그대로 두고 값을 두 개 늘렸다.**
호출처는 `:1361`(목표 포트폴리오)과 `:1495`(매매일지) 둘뿐이다.

**확률 셋은 하단을 잔여로 계산한다** — `100 − round(상단) − round(Base)`. 합이 항상
100이 되게 하려는 것이다. 그래서 1/3씩이면 `33/33/34` 로 나온다. 버그가 아니다.

Base 미입력 레거시 보유분은 `◆` 와 확률 묶음을 통째로 뺀다(`kellyOf` 와 같은 판정).

## 손대지 말 것

- **`docs/analysis/` 를 `.gitignore` 에서 빼지 말 것.** 위 «알아야 할 것» 두 번째 항목의
  세 가지 이유. 사용자가 이번 세션에 명시적으로 결정했다. 필요하면 다시 물을 것 —
  **묻지 말고 커밋하면 되돌릴 수 없다.**
- **`scenLine()` 의 확률 잔여 계산**(`100−pBull−pBase`). 셋을 각각 반올림하면 합이 99나
  101이 된다. `33/33/34` 는 그래서 나오는 값이고 의도된 것이다.
- **화면에서 `prob` 을 다시 "승률"로 부르지 말 것.** v5 에서 `prob` = P(Bull) 이고
  나머지는 `pBase` 와 `pBear`(=1−prob−pBase)로 갈린다. "승률"로 되돌리면 사용자가
  넣는 숫자의 의미가 조용히 달라진다 — **예외가 안 나고 배분만 틀린다.** 화면 표기는
  `상단확률`·`Base확률` 한 쌍으로 유지한다.
- **`kellyOf` 의 선언 형태**(`function kellyOf(h){`) — `test_pipeline.js` 의 `grab()` 이
  중괄호 균형으로 이 형태를 찾는다. 화살표 함수로 바꾸면 테스트가 통째로 죽는다.
  `compute`·`kelly3`·`livePlanHoldings`·`isThesisReject` 도 같다. **`scenLine` 도 이제
  같은 방식으로 뽑아 쓸 수 있다** — 이번 검증이 그렇게 했다.
- **`test_pipeline.js:31` 의 `constOf(...)` 목록** — `MAX_SINGLE`·`THIN_DOWNSIDE` 둘뿐이다.
  여기 없는 상수를 `compute()` 에서 참조하면 테스트가 `ReferenceError` 로 죽는다.
- **`kelly3` 의 `α≈0 ∧ β≈0` 가드.** `p_base=1` 처럼 "확실히 제자리"인 입력에서 0/0을 막는
  유일한 장치다.
- **`thinDown` 이 `Math.abs(Math.min(...rs))` 기준인 것.** 순서 검증이 있는 한 수학적으로는
  `rs[2]` 와 같지만, 순서 검증이 미래에 느슨해지면 마지막 방어선이 된다.
- **`kellyOf` 의 순서 검증**(`상단 ≥ Base ≥ 하단`). Base·Bear를 바꿔 적어도 수학은 조용히
  돌아간다 — 화면의 "Base" 라벨이 거짓말하는 걸 막는 **유일한** 장치다. 돌연변이 테스트로
  확인: 이 줄을 지우면 딱 그 검증 하나만 FAIL한다.
- **`thesisWorsened` 의 `prevPBase!==undefined` 가드**(`:1428`). 3-시나리오 이전 원장
  항목에는 `prevPBase` 가 없어, 가드를 빼면 `NaN` 비교가 조용히 false 가 된다.
- **마이그레이션에 기본값을 채우지 말 것.** v4→v5는 스냅샷 버전 표기만 갱신하고 `base` 는
  비워둔다. 추정값을 채우면 "아무도 생각한 적 없는 숫자"가 조용히 배분을 움직인다.
- **`compute()` 의 `rel = w/equityScale` 한 줄**(`:1003`). 렌더 4곳이 `rel × equityScale`
  로 최종비중을 복원한다. `rel` 을 켈리 몫(`f/posSum`)으로 되돌리면 상한이 걸린 종목의 화면
  숫자가 조용히 커진다 — 테스트 `상한 — rel × equityScale 항등식` 그룹이 이걸 지킨다.
- **종목 색을 `colorOf` 맵(종목 id 기준)으로 매기는 것**(`:1310`). 배분바는 `pos`, 카드는
  `rows` 를 돌기 때문에 각자 인덱스로 매기면 보류 종목이 끼는 순간 그 뒤가 통째로 밀린다.
  **예외가 안 나고 화면만 조용히 거짓말한다.**
- **`--demo` 픽스처 값**(`docs/superpowers/build-selfcheck.js`). 값이 바뀌면 화면 비교의
  기준이 사라진다(§7-D25). 바꿔야 하면 그 파일 주석의 기대 배분표와 체크리스트 2단계의
  표를 **함께** 갱신할 것. **단 `startQ` 만은 `currentQGuess()` 다**(§7-D26).
- **`load()` 안의 `advanceStartQ` 호출**(`:1745`). 이 호출이 빠져도 `test_pipeline.js` 는
  **129건 전부 통과한다** — 순수 함수는 멀쩡하기 때문이다. 자체 검사 26번만 FAIL 한다.
  단위 검사가 지켜주지 않는 자리다.

### ⚠ 3-시나리오까지 되돌리기 — 데이터가 안전하지 않다

**`prob` 필드의 의미가 바뀌었다.** v4에서는 "승률"(나머지 1−p가 전부 하단)이고, v5에서는
"P(Bull)"(나머지가 Base와 Bear로 나뉜다). 필드 이름과 타입이 같아서 옛 빌드가 **에러 없이
읽고 조용히 다르게 해석한다.**

실측 — 현재가 100 · Bull 150(25%) · Base 120(50%) · Bear 70(25%) 종목:

| 빌드 | f | 결과 |
|---|---|---|
| 새(3-시나리오) | **1.6085** | 배분에 포함 |
| 옛(같은 데이터) | **−0.6667** | **음수 켈리로 배분에서 제외** |

종목이 계획에서 통째로 사라지는데 경고가 없다. 되돌리려면 순서가 있다:

1. 폰에서 `⬇ 내보내기`로 v5 백업을 받아둔다 (나중에 다시 켤 때 필요하다)
2. 코드를 revert 해서 배포한다
3. **v5 이전 백업으로 `⬆ 가져오기`** 하거나, 각 종목의 `prob` 을 옛 의미(승률)로 손으로
   고친다. 안 하면 종목들이 배분에서 사라진 채로 남는다

계산 수준의 롤백(코드는 새 빌드, 값만 옛 공식으로)은 `kelly3` 에 `p_base=0, r_base=0` 을
넘기면 정확히 같은 값이 나온다 — 축퇴 성질이 그 경로를 겸한다(PRD §7-D20).

**교훈**(§7-D21): 필드를 **추가**하는 것과 기존 필드의 **의미**를 바꾸는 것은 다르다.
후자는 스냅샷 버전만으로 방어되지 않는다 — 옛 빌드는 버전을 보고 거부하지 않고 그냥 읽는다.
의미를 바꾸면 저장 포맷만이 아니라 **그 필드를 부르는 화면 이름도 전부 따라와야 한다.**
