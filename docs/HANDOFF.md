## 알아야 할 것

**이번 세션 신규 — 모르면 문서를 망가뜨린다:**

- **⚠ `verify-uber-rim.js` 는 「문서 전체에서 첫 번째 매칭」에 의존한다.**
  `study.match(/FY2025 \*{0,2}\$([\d.]+)B\*{0,2}/)` 로 `uber-스터디.md` 를 훑어
  **처음 걸리는 값**을 쓴다(현재 CH.06 자사주 절의 `FY2025 $6.52B`, 스크립트 330행).
  문단 순서를 바꾸다 그 앞에 같은 패턴이 생기면 **스크립트가 조용히 다른 값을 집는다.**
  기존 경고("검산 스크립트가 문서를 파싱한다")보다 한 단계 구체적인 함정이다.
- **⚠ `verify-uber-rim.js` 는 `uber-분석.md` 를 통째로 펴서 리터럴 공백으로 문장을 찾는다.**
  ```js
  const flat = anal.replace(/\n/g, ' ');                    // 문서 전체가 한 줄이 된다
  flat.match(/\*\*대표 (\d+)% · 밴드 (\d+)~(\d+)%\*\*/)        // 공백이 리터럴이다
  ```
  줄바꿈이 **공백 1개**로 바뀌므로 두 줄에 걸친 문장이 매칭된다. **빈 줄을 넣거나 줄을 합치면
  그 지점의 공백 수가 달라져 매칭이 깨진다.** 이런 정규식이 25개고 상당수가 리터럴 공백을 쓴다.
  그래서 이번 세션은 분석 문서에서 **문장을 한 글자도 고치지 않았다** — 빈 줄만 넣었다.
  고치려면 load-bearing 문장의 줄 번호를 먼저 뽑아라(이번엔 37줄이었다):
  `grep -n 'anal\.match\|flat\.match' docs/analysis/tools/verify-uber-rim.js`
- **⚠ 반대로 tsmc 분석 문서는 산문 편집이 안전하다** — `verify-tsmc-anchor` 는 ANCHOR 표·
  시나리오 표·금지패턴만 보고 문서를 펴지 않으며, `verify-tsmc-depreciation` 은 **파일을 아예
  안 읽는다**(20-F 수치로 자체 계산). 그만큼 문서 드리프트를 못 잡는다는 뜻이기도 하다.
- **⚠ 표 안에 빈 줄을 넣지 말 것** — 시나리오·IRR 표 정규식이 `\|…\|\n` 연속 행을 요구한다.
- **⚠ 그래서 PASS/FAIL 만 보면 안 된다 — 출력 전문을 대조할 것.**
  값이 바뀌어도 스크립트는 통과한다(위 대조는 `note()` 라 판정하지 않는다).
  문서를 고치기 **전에** 기준선을 뜨고 나중에 `diff` 한다:
  ```
  for s in verify-uber-rim verify-uber-anchor verify-tsmc-anchor verify-tsmc-depreciation; do
    node docs/analysis/tools/$s.js > /tmp/base-$s.txt 2>&1; done
  # …편집 후…
  node docs/analysis/tools/$s.js | diff /tmp/base-$s.txt -
  ```
  스터디 편집 때는 네 스크립트가 **바이트 단위로 동일**했다. 분석 편집 때는 **줄 번호만**
  달라졌다(`L539`→`L561`) — 그때는 줄 번호를 지우고 비교하고, **검사 건수가 같은지도 볼 것**
  (조용히 건너뛴 검사가 없다는 증거다):
  ```
  norm() { sed -E 's/L[0-9]+ 에/L# 에/g; s/@[0-9]+행/@#행/g'; }
  diff <(norm < /tmp/base-X.txt) <(norm < <(node tools/X.js))
  ```
- **⚠ 어느 스크립트가 어느 파일을 읽는지**: `verify-uber-rim` 만 `uber-스터디.md` 를
  읽는다(+`uber-분석.md`·`index_roe.html`). 나머지 셋은 `-분석.md` 와 posts 만 읽는다.
  즉 **스터디 편집은 uber 만 위험하고, 분석 편집은 셋 다 위험하다.**
- **`verify-lossless-edit.js` 사용법** — 문서를 고쳐 쓴 뒤 사실이 빠졌는지 본다.
  ```
  node docs/analysis/tools/verify-lossless-edit.js companies/uber/uber-스터디.md          # HEAD 와
  node docs/analysis/tools/verify-lossless-edit.js companies/uber/uber-스터디.md fe6ceb0  # 특정 커밋과
  ```
  숫자 토큰 · 영문 원문 인용 · 출처 태그 개수 · 제목 · 백틱 참조를 **다중집합으로** 비교한다.
  순서 변경은 통과하고 누락만 잡는다. **새로 생긴 숫자도 FAIL** 이다 — 편집 중 만들어낸
  수치는 사실이 아니기 때문이다. 실제로 이번에 netflix 에서 `(공시)` 1건과 `FY2025` 1건이
  이렇게 잡혔다. **눈으로는 안 잡힌다.**
