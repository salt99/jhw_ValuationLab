# 켈리 3-시나리오 확장 — 설계

**날짜**: 2026-08-13 · **도구**: TOOL 04 (`index_kelly.html`) · **상태**: 설계 승인됨

## 문제

밸류에이션 분석은 **Bear / Base / Bull 세 개의 적정가**로 끝난다 (TSMC 문서 APP.E:
PBR 3.05 / 5.70 / 8.04). 그런데 켈리 플래너는 상단·하단 **두 개**만 받는다.

세 시나리오를 둘로 욱여넣는 방법은 전부 정보를 버린다. Base를 빼면 기준선이 사라지고,
Bear를 빼면 하방이 사라지며, 셋을 평균내면 분석 문서의 규칙 7(*"시나리오를 평균내지
않는다"*)을 정면으로 위반한다. **입력 구조를 분석 구조에 맞춘다.**

부수 효과: 사다리 구간에서 매수할 때 상방이 둘(Bull·Base)이 되는데, 2-시나리오로는
애초에 표현 자체가 불가능했다.

## 수식 — 닫힌해가 있다

`E[log(1+f·r)]` 최대화를 미분하면 `Σ pᵢrᵢ/(1+f·rᵢ) = 0`. 분모를 걷어내면 **f에 대한
2차식**이 된다. 수치해·반복 탐색이 필요 없다.

```
rᵢ = (목표가ᵢ − 현재가) / 현재가        i ∈ {bull, base, bear}

α·f² + β·f + γ = 0
  α = r_bull · r_base · r_bear
  β = Σᵢ pᵢ·rᵢ·(rⱼ + rₖ)                (j,k = i 아닌 나머지 둘)
  γ = Σᵢ pᵢ·rᵢ = E[r]

|α| < 1e-12 → f = −γ/β                  (1차 축퇴)
              단 |β| < 1e-12 이면 퇴화 → err
그 외        → 두 근 중 모든 i 에서 1 + f·rᵢ > 0 인 근
```

`α ≈ 0` 인데 `β ≈ 0` 인 경우가 실제로 존재한다: `p_base = 1`(나머지 확률이 0) 이면
"확실히 제자리"라는 뜻이라 베팅할 대상이 없다. 세 rᵢ 가 모두 0 인 경우도 같다.
나눗셈이 `Infinity`/`NaN` 을 뱉기 전에 err 로 잡는다.

α가 세 수익률의 곱, γ가 기대수익률이라는 것은 우연이 아니라 전개의 결과다
(`p₁+p₂+p₃ = 1` 이 α를 `r₁r₂r₃` 로 접는다).

### 근 선택

log 의 정의역 `1 + f·rᵢ > 0` 안에서 목적함수는 오목(concave)하므로 정류점이 **정확히
하나**다. 따라서 두 근 중 정의역을 만족하는 것은 수학적으로 하나뿐이고, 그것이 최대점이다.

구현에서는 그래도 세 갈래를 다 처리한다 — 부동소수점 오차로 경계에서 둘 다 통과하거나
둘 다 탈락할 수 있기 때문이다. **하나 통과** → 그 근. **둘 통과** → `E[log]` 가 큰 쪽
(수학적으로는 일어나지 않지만 경계 오차의 안전망). **둘 다 탈락** → err.

### 축퇴 검증 — 이것이 안전성의 근거

`base = price` (r_base = 0), `p_base = 0` 을 넣으면 α = 0 이 되어 1차식이 되고,
전개하면 **정확히 기존 공식 `f = p/a − q/b`** 다.

브레인스토밍 단계에서 검증 완료 (무식한 수치 최대화와 대조):

| 케이스 | 닫힌해 | 수치해 |
|---|---|---|
| TSMC PBR 5.0 매수 (8.04/5.70/3.05, 25/50/25) | 0.972905 | 0.972904 |
| 상방 치우침 (1.2/0.3/−0.4) | 1.108358 | 1.108358 |
| 하방 치우침 (0.5/−0.1/−0.6) | −0.379632 | −0.379632 |
| 2-결과 축퇴 (400/264/200, p 0.55) | 1.395221 | 1.395221 = p/a−q/b |

## 켈리 전제와 한계 — 수식이 맞는 것과 쓸 자격이 있는 것은 다르다

유도는 검증됐다. 그러나 켈리는 **1기간 베팅이 반복된다**는 전제 위의 정리이고, 주식
포지션은 그 전제를 온전히 만족하지 않는다. 아래는 이번 변경으로 새로 생긴 것이 아니라
대부분 기존 2-시나리오 도구에서 상속된 것이지만, 시나리오가 셋이 되면 "분포를 다 덮었다"는
착각이 생기기 쉬워 명시한다.

### 1. 기간 일관성 — 코드가 아니라 사용 규율

적정가는 "언제" 도달하는 값인지 도구가 묻지 않는다. 같은 TSMC 시나리오라도 도달 기간을
어떻게 가정하느냐로 f 가 5배까지 갈린다:

| 도달 기간 가정 | f |
|---|---|
| 원시 수익률 그대로 | 0.97 |
| 3년 (연율화) | 1.87 |
| 5년 (연율화) | 2.78 |
| 10년 (연율화) | 5.05 |

**연율화하지 않는다.** 연율화는 "매년 독립적으로 다시 뽑는다"는 모델인데, 실제로는
한 번 뽑고 N년 걸려 해소되는 단일 베팅이다. 원시 수익률이 맞다.

대신 두 가지 전제가 붙는다:

- 세 시나리오가 **같은 기간에 해소**된다고 가정한다 (Bear 만 1년, Bull 만 20년이면 무효)
- **종목 간 기간이 다르면 f 비교가 무의미하다.** TSMC 는 해자 N=15년 전제의 적정가다.
  3년 관점으로 넣은 종목과 같은 `posSum` 에 넣으면 상대 배분이 왜곡된다

→ 새 필드로 기간을 받지 않는다(P6). 종목 간 관점 기간을 맞추는 것은 사용자의 규율이다.

### 2. Bear 가 얕으면 f 가 폭발한다

`thinDown` 은 **경고만 하고 막지 않는다.** 실측:

| 최악 시나리오 | f |
|---|---|
| −30% | 1.27 |
| −15% | 3.60 |
| −8% | 7.83 ← `thinDown` |
| −3% | 23.29 ← `thinDown` |

f = 23 이면 `rel = f/posSum` 에서 그 종목이 사실상 전부를 가져가고 `MAX_SINGLE`(40%)
에서야 잘린다. 시나리오 칸이 늘어난 만큼 얕은 Bear 를 실수로 넣을 경로도 늘어난다.
**`thinDown` 판정을 가장 나쁜 rᵢ 기준으로 확실히 옮기는 것이 이번 작업에서 특히 중요하다.**

### 3. 세 시나리오는 밸류에이션 분포이지 파산 분포가 아니다

Bear 3.05 는 *"착시론이 실현됐을 때의 적정가"* 이지 *"대만 유사시"* 가 아니다. 켈리는
최악을 Bear 로 절단한 분포를 보므로 **왼쪽 꼬리가 잘린 만큼 f 를 낙관적으로 낸다.**

분석 문서가 이미 *"대만 지정학은 기각 조건이 아니라 Kelly 사이징의 tail risk 파라미터"*
라고 정한 것과 같은 이야기다. 꼬리는 여전히 **포지션 총량 상한**으로 도구 밖에서 처리한다.
4번째 시나리오를 넣지 않는 이유이기도 하다 — 4개부터는 닫힌해가 사라진다.

### 4. 상속되는 한계 (§7-D5) — 이번 변경으로 나아지지 않는다

- **f > 1 은 레버리지를 뜻하지만** 도구는 정규화해 상대 가중치로만 쓴다. Half-Kelly 는
  총노출 결정에만 관여한다
- **종목 간 상관관계를 무시한다.** 진짜 다자산 켈리는 공분산이 필요하다. TSMC 는
  인적자본(반도체 커리어)·기존 포지션과 강상관이라 정규화가 구조적으로 과대배분한다 —
  분석 문서의 **3중 집중 심사**가 도구 밖에서 이를 막는 장치다

### 확인된 것 — 총 주식 노출은 안 흔들린다

Base 추가로 f 크기가 변해도 `equityScale = min(posSum,1)×0.5` 가 흡수한다. 실측:
2-시나리오 3종목(각 f=1.395) → `posSum` 4.185, 3-시나리오(각 f=1.992) → 5.975,
**양쪽 다 `equityScale` 50%**.

단 f 자체는 변한다 (예: 1.395 → 1.992). 수식 때문이 아니라 확률 배분이 바뀌기 때문이며
(하방 확률 45%→25%), 따라서 **마이그레이션 후 종목 간 상대 비중이 재배치된다.**
정상 동작이지만 예상하고 있어야 한다.

## 코드 배치 — 테스트 가능성이 배치를 정한다

`kellyOf()` 는 `index_kelly.html:875` 로 **PURE 블록(687-776) 밖**에 있다.
`test_pipeline.js` 는 두 경로로 코드를 가져온다:

- PURE 블록 → 정규식으로 통째 추출 → `api.*`
- `kellyOf`·`compute`·`livePlanHoldings` → `grab()` 이 중괄호 균형으로 선언만 잘라내
  `alloc` 샌드박스에 올림

따라서 **순수 수식 `kelly3(rs, ps)` 를 PURE 블록 안에 둔다.** 그러면 `api.kelly3` 로
직접 단위 검증이 가능하다. `kellyOf()` 는 그것을 호출하는 얇은 껍데기가 된다.

**`test_pipeline.js` 의 `alloc` 배열에 `grab('kelly3')` 를 추가해야 한다.** 빼먹으면
샌드박스 안에서 `kelly3 is not defined` 로 `compute` 검증이 통째로 죽는다.

`kellyOf` 의 **선언 형태(`function kellyOf(h){`)는 바꾸지 않는다** — `grab()` 이
이 형태를 찾는다 (HANDOFF 경고 사항).

## 데이터 모델 · v5

```js
{ …기존, price, up, down, prob,   // prob = P(Bull) — 기존 필드 재사용
  base:  300,                      // 신규 · 없으면 켈리 보류
  pBase: 0.50 }                    // 신규 · P(Bear) = 1 − prob − pBase 로 도출
```

**확률은 셋 다 입력받고 합을 검증하되 저장은 둘만 한다.** 셋을 저장하면 마이그레이션
버그로 합이 깨졌을 때 어느 값이 진실인지 알 수 없다. 합 검증이 입력 시점에 이뤄지므로
도출은 정확하다.

### v4 → v5 마이그레이션 — 아무것도 채우지 않는다

`base` 가 없는 기존 종목은 **그대로 둔다.** 켈리는 계산하지 않고 보류한다.
`load()` 의 `const ver=d.v||1`(`:1631`) 분기와 같은 자리에 `ver<5` 를 추가하되,
하는 일은 스냅샷 버전 표기 갱신뿐이다.

기본값을 추정해 채우지 않는 이유: 아무도 생각한 적 없는 숫자가 켈리에 들어가 목표
배분을 움직인다. 빈 칸은 "아직 판단하지 않았다"는 정직한 상태다.

**대가**: 마이그레이션 직후 보유 종목 전부가 동시에 켈리 보류가 되어 목표 배분과 분기
매매일지가 빈다. Base 를 채울 때까지 도구가 사실상 멈춘다. 이것은 결함이 아니라
**의도된 forcing function** 이다 — 전 종목의 Base 를 한 번 생각하게 만든다.
칸 회수 강제 등재(§7-D18)와 같은 결이다.

`dataSnapshot()`(`:1597`) 의 `v:4` → `v:5`. 배열을 통째로 직렬화하므로 백업·복원은
자동으로 따라온다.

## 검증 규칙 — `kellyOf()` 의 반환

| 조건 | 반환 |
|---|---|
| `base` 미입력 (`undefined`/`null`) | `{f:null, err:'Base 미입력 — 켈리 보류'}` |
| 모든 rᵢ ≥ 0 (하방 없음) | `{f:null, err:'하방 시나리오가 없습니다'}` — 켈리 발산 |
| 유효근 없음 / 근이 둘 다 정의역 위반 | `{f:null, err:'시나리오가 퇴화했습니다'}` |
| 모든 rᵢ ≤ 0 (상방 없음) | `f < 0` 으로 정상 반환 → 기존 §7-D6 배분 제외가 처리 |
| **가장 나쁜** rᵢ 의 절댓값 < `THIN_DOWNSIDE`(0.10) | `thinDown: true` — 기존 경고 경로 유지 |

`thinDown` 은 반드시 `Math.min(...rs)` 기준이어야 한다. 기존 코드가 `a`(하단) 하나만
보던 자리다 — 3-시나리오에서 하단 칸이 최악이라는 보장이 없으므로(아래 순서 검증이
있어도 방어적으로) 최솟값으로 판정한다.

기존 err 문구 `하단이 현재가 이상` · `상단이 현재가 이하` 는 3-시나리오에서 의미를
잃으므로 위 표로 **대체**한다.

**TSMC 현재가(PBR 10.5)는 4번째 줄에 걸린다** — 세 목표가 전부 현재가 아래라
`E[r] < 0` → `f < 0` → 배분 제외. 도구가 "사지 마라"고 답하는 정상 동작이다.

`thinDown` 의 소비처 4곳(`:986`, `:1254`, `:1578`, `:2482`)은 플래그 이름과 의미가
그대로이므로 수정 불필요하다.

## 입력 화면 — 세 곳

같은 3행이 **종목 추가 폼 · 재평가(📊) · 수정(✎)** 에 들어간다.

```
현재가     [ 264 ]
─────────────────────────────
상단 Bull  [ 400 ]  확률 [ 25 ]%
Base       [ 300 ]  확률 [ 50 ]%
하단 Bear  [ 200 ]  확률 [ 25 ]%
                      합 100% ✓
```

- 기존 필드 재사용: `i-up`(`:354`) / `i-prob`(`:359`) / `em-up`(`:481`) /
  `em-prob`(`:486`) / `re-up`(`:521`) / `re-prob`(`:526`)
- 신규 필드: `i-base`·`i-pbase`, `em-base`·`em-pbase`, `re-base`·`re-pbase`
- 합 표시는 세 확률 입력의 `input` 이벤트로 갱신. **합이 100 이 아니면 저장 거부**
  (`setStatus(..., true)` 로 기존 오류 표시 관행을 따른다)
- Bear 확률은 입력란이지만 저장되지 않는다 — 합 검증에만 쓰인다
- **순서 검증: `Bull ≥ Base ≥ Bear` 가 아니면 저장 거부.** 수학은 순서와 무관하게
  돌아가므로 Base·Bear 를 바꿔 적어도 조용히 통과한다 — 그러면 라벨이 거짓말을 하고
  화면의 "Base" 가 실제로는 최악 시나리오가 된다. 라벨이 이 기능의 전부이므로 막는다

### 역할 분담 — 어디서 Base 를 채우나

| 경로 | 용도 | 원장 이력 |
|---|---|---|
| 수정 (✎) | 마이그레이션으로 **처음** 채울 때 | 안 남김 |
| 재평가 (📊) | 이후 Base 를 **바꿀** 때 | 남김 (근거 필수) |

마이그레이션은 판단의 변경이 아니라 없던 차원을 처음 적는 것이다. 재평가로 처리하면
`상단 400 → 400` 같은 의미 없는 변경 이력이 종목마다 하나씩 쌓인다.

보유 카드에 `⚠ Base 미입력 — 켈리 보류` 배너를 단다. 칸 회수 미등재 배너와 같은 방식.

## ⚠ 단위 주의 — 코드 아님, 사용법

분석 문서는 **PBR** 단위이고 도구는 **주가($)** 단위다.

켈리 `f` 만 보면 rᵢ 가 비율이라 PBR 을 그대로 넣어도 값이 같다(스케일 불변). 그러나
**주수 계산이 깨진다** — 매수 금액을 5.00 으로 나누면 엉뚱한 주수가 나온다.

→ TSMC 를 입력할 때 PBR 을 BPS 로 환산한 **$ 값**을 넣는다. 자동 환산은 만들지 않는다
(BPS 입력을 새로 받아야 하고, BPS 는 분기마다 변한다).

| N-시나리오 일반화 | 3개는 닫힌해가 있고 4개부터 수치해가 필요해진다. 필요가 확인되기 전엔 기각 |
| 확률 자동 배분·슬라이더 | 셋 다 명시 입력으로 결정됨 |
| PBR ↔ $ 자동 환산 | BPS 입력이 새로 필요하고 분기마다 변한다 |
| 기존 종목 Base 일괄 입력 화면 | 마이그레이션 끝나면 영영 안 쓰는 화면 |
| 시나리오별 확률의 이력 추적 | 재평가 원장이 이미 담는다 |
| 도달 기간(N) 입력 필드 | 세 시나리오가 같은 기간이면 f 가 안 변한다. 종목 간 기간을 맞추는 것은 사용자 규율의 몫 (위 «전제와 한계» 1) |
| 4번째 꼬리 시나리오 | 4개부터 닫힌해가 사라지고, 꼬리는 포지션 총량 상한이 이미 담당한다 |

## 검증 (P5)

### `test_pipeline.js` — 순수 함수

- `kelly3` 축퇴: `base=price, pBase=0` 이면 `p/a − q/b` 와 1e-9 이내 일치 (기존 3케이스)
- `kelly3` vs 수치 최대화: 위 표 4케이스를 2e-4 이내로 대조
- 근 선택: 정의역 밖 근을 고르지 않는지
- err 경로 6종 (Base 미입력 · 하방 없음 · 유효근 없음 · α≈0∧β≈0 · 순서 위반 · 확률 합)
- `thinDown` 이 `Math.min(...rs)` 기준인지 — 하단이 최악이 **아닌** 입력으로 확인
- 얕은 하방 실측 재현: 최악 −3% 에서 f ≈ 23.29 이고 `thinDown` 이 켜지는지
- `compute()` 회귀: Base 없는 기존 종목이 배분에서 빠지고, 살아있는 종목 목표가
  **줄지 않는지** (§7-D18 검증과 같은 형태 — "커진다"가 아니라 "줄지 않는다")

## 기각 조건 — 언제 되돌리나

- 실사용에서 Base 와 Bull 이 늘 같은 값으로 적힌다 → 시나리오가 셋일 이유가 없다
- 확률 합 맞추기가 번거로워 입력을 회피하게 된다 → 둘 입력·하나 자동으로 후퇴
- 마이그레이션 후 한 분기 안에 Base 를 다 못 채운다 → forcing function 이 과했다는 증거
- 종목마다 도달 기간 관점이 제각각이 되어 f 비교가 무의미해진다 → 기간 필드를 받거나
  켈리를 상대 배분에 쓰는 것 자체를 재검토 (§7-D5 로 소급)

되돌리기: `base` 를 무시하고 `kelly3` 에 `p_base=0, r_base=0` 을 넘기면 기존 동작으로
정확히 복귀한다. 축퇴 성질이 롤백 경로를 겸한다.
