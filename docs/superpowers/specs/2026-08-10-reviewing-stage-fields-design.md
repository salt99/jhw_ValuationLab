# 검토중 단계 정보 입력 — 설계

**날짜**: 2026-08-10 · **도구**: TOOL 04 (`index_kelly.html`) · **상태**: 설계 승인됨

## 문제

후보 파이프라인의 `검토중` 항목은 **이름과 경과일뿐**이다. 실사용에서 세 가지가 걸렸다:

1. **왜 보기 시작했는지 잊는다** — 며칠 지나면 이 종목을 후보에 넣은 이유가 기억나지 않는다
2. **어디까지 봤는지 모른다** — TOOL 01/02/03 중 어디까지 통과했는지 목록에서 안 보인다
3. **편입·기각을 누를 때 근거가 없다** — 판단 순간에 참고할 메모가 없어 기억에 의존한다

이와 별개로, 매도 사유 `원 논지 훼손`의 **"원 논지"가 어디에도 기록돼 있지 않다.**
무엇이 깨졌는지 판정하려면 대조할 원문이 있어야 한다.

## 성격 — 작업 기억이지 증거가 아니다

기각 원장(§4.4)은 3년 뒤 반증을 위한 **증거**라서 14일 유예·소급 배지·잠금이 걸려 있다.
여기서 만드는 것은 검토 중에 쓰는 **작업 기억**이다. 사용자가 명시적으로 그렇게 판단했다.

따라서 **잠금·유예·소급 판정을 걸지 않는다.** 언제든 자유롭게 고친다.
유일한 예외가 `origin`(계기)인데, 이것만은 편입 시 `holdings.thesis`로 승계되어
장기 보존된다.

## 데이터 모델

```js
// candidates[] — 신규 필드 3개, 전부 선택적
{ id, name, status, startDate,                    // 기존
  origin:     '창고형 리테일 해자',                  // 계기. 등록 시 입력, 선택
  stage:      {circle:true, premium:true, val:false},  // 진행 체크
  reviewNote: '10-K 3장까지 읽음' }                  // 작업 메모

// holdings[] — 신규 필드 1개
{ id, name, price, up, down, prob, …,             // 기존
  thesis: '창고형 리테일 해자' }                     // 원 논지. 선택
```

### 이름을 이렇게 고른 이유

- **`reviewNote`** — `c.note`는 **이미 기각 메모**다(`index_kelly.html:1964`). 재사용하면
  검토 메모와 기각 메모가 서로를 덮어쓴다.
- **`h.thesis`** — 미사용 확인. `SELL_REASONS.thesis`(`:1113`)와 `REJECT_LABELS.thesis`(`:1682`)는
  라벨 맵의 **키**이지 보유 종목의 필드가 아니다.
- **`stage`는 객체** — 배열이면 순서·중복을 방어해야 한다. 세 불리언이 의도를 그대로 담는다.

### 마이그레이션 — 없음

세 필드 모두 선택적이라 **스냅샷 버전은 v4 그대로**다. 기존 데이터는 필드가 없는 채로 읽히고,
없으면 화면에 안 나온다. `dataSnapshot()`(`:1554`)이 `holdings`·`candidates`를 통째로
직렬화하므로 **백업·복원도 자동으로 따라온다.** PRD §5 키 레지스트리 변경 없음.

## UI 변경 — 네 곳

### ① 후보 등록 팝업 (`index_kelly.html:553-567`)

입력란 한 줄 추가. **비워도 등록된다.**

```
종목명   [ Costco              ]
왜 보나  [ 창고형 리테일 해자     ]   ← 신규 · 선택
────────────────────────────────
검토 시작일은 등록 시각으로 자동 기록됩니다 …
[ 검토중으로 등록 ]
[ 바로 기각 등재  ]
```

필수화하지 않는 이유: 종목을 발견한 순간 빠르게 적어두는 가벼움이 파이프라인의
진입 마찰을 낮춘다. 강제하면 그 가벼움이 사라진다.

`바로 기각 등재` 경로도 `origin`을 함께 넘긴다 — 기각 카드에 계기가 표시되어야 하기 때문.
구체적으로 `pl-save-reject` 핸들러(`:1933`)가 `openRejectModal(null, {name})` 대신
`{name, origin}`을 넘기고, `rj-save`가 후보를 만들 때(`:1955`) 그 값을 심는다.

### ② 검토중 카드 (`index_kelly.html:1765-1772`)

```
Costco                    42일 · 2026-06-29
"창고형 리테일 해자"                        ← origin 있을 때만
☑능력범위 ☑프리미엄 □밸류에이션              ← 신규
[기각] [편입] [✎ 메모] [삭제]
```

- 체크박스는 진짜 `<input type="checkbox">`다. 탭하면 브라우저가 표시를 바꾸고,
  핸들러는 `candidates[].stage`를 갱신한 뒤 **`save()`만** 부른다.
  `render()`는 부르지 않는다 — 목록을 다시 그리면 모바일에서 스크롤이 튄다.
- `✎ 메모` → 작은 모달에서 `origin`·`reviewNote`를 함께 수정한다.
- `origin`·`reviewNote`는 `escapeHtml()` 필수 (파일 내 기존 관행).
- **모바일 위험**: 체크박스 3개가 폰 폭에서 한 줄에 들어가야 한다. 넘치면 wrap 허용.
  P3(모바일 우선) 확인 항목이다.

### ③ 종목 추가 폼 (`index_kelly.html:345`) + 편입 경로 (`:1873-1877`)

```
종목명 [ Apple              ]
논지   [ 생태계 잠금효과       ]   ← 신규 · 선택
현재가 [ 264 ]  …
```

- `data-pladopt` 핸들러(`:1873`)에 `$('i-thesis').value = c.origin || ''` 한 줄 추가.
  자동 채움은 **초기값일 뿐**이고, 사용자가 고치면 고친 값이 저장된다.
- 제출 핸들러(`:1079`)에서 `thesis`를 읽어 holding에 넣는다. 빈 문자열이면 필드를 만들지 않는다.
- 폼 리셋(`:1103`)에 `i-thesis` 초기화를 추가한다 — **빠뜨리면 다음 종목에 이전 논지가 남는다.**
- `pendingAdoptId` 로직(`:1097-1101`)은 **건드리지 않는다.** 논지는 폼 값에서 읽으므로
  후보 제거 로직과 무관하다.

### ④ 칸 회수 모달 — 원 논지 표시

`h.thesis`가 있을 때만 한 줄 뜬다.

```
사유: 원 논지 훼손
원 논지: "창고형 리테일 해자"      ← 무엇이 깨졌는지 대조
재검토 트리거 [                 ]
```

기존 보유 종목은 `thesis`가 없으므로 이 줄이 안 뜬다 — 지금과 같은 화면이다.

## 상태 전이 — 검토 필드의 수명

```
[+ 후보 등록]  origin 입력 (선택)
   │
   ▼
▸ 검토중      origin · stage · reviewNote 자유 편집
   │
   ├─ 편입 ──▶ origin → holdings.thesis 로 승계
   │           stage · reviewNote 는 버린다 (후보 자체가 사라짐)
   │
   ├─ 기각 ──▶ origin 유지 · 기각 카드에 표시
   │           stage · reviewNote 는 삭제한다  ← 결정 A
   │
   └─ 삭제 ──▶ 전부 사라짐 (변경 없음)
```

기각 카드(`rejectCard`, `:1688`)에서 `origin`은 검토중 카드와 **같은 모양**으로 뜬다 —
종목명 아래 인용부호 한 줄. 없으면 그 줄이 없다. 체크박스 줄은 기각 카드에 없다.

**기각 시 `stage`·`reviewNote`를 지우는 이유**: 편입과 대칭이고, 남길 가치가 있는 내용은
기각 모달의 `메모`(`rj-note`)에 옮겨 적으면 된다 — 그게 그 필드의 용도다. 남겨두면
아무도 읽지 않는 죽은 데이터가 된다.

구현: `rj-save` 핸들러(`:1940`)에서 신규 등재일 때(`!rjCtx.editing`) `delete c.stage;
delete c.reviewNote;`. 칸 회수 자동 등재는 후보를 새로 만드는 경로라 애초에 두 필드가 없다.

## 안 만드는 것 (P6 과공학 경계)

| 안 만드는 것 | 이유 |
|---|---|
| 체크박스 ↔ TOOL 01/02/03 자동 연동 | **PRD §5 키 공유 금지로 불가능.** 수동 자기보고임을 전제로 설계했다 |
| 계기 필수화 | 등록 마찰이 생기고 기존 데이터가 깨진다 |
| 기존 보유 종목 논지 소급 입력 | 이미 주가를 아는 상태의 사후 서술. 검토 시작일을 안 받는 것과 같은 이유 |
| 진행 상태 기준 정렬·필터·알림 | 검토중 항목이 5개 안팎이다. 스캔으로 충분하다 |
| 검토 필드의 14일 잠금 | 증거가 아니라 작업 기억이다 |

## 검증 (P5)

### `test_pipeline.js` — 순수 함수

- 편입 시 `origin`이 `h.thesis`로 들어간다
- `origin`이 비면 `h.thesis`를 만들지 않는다
- 후보를 안 거친 직접 추가는 폼 값이 그대로 `h.thesis`가 된다
- 기각 등재 시 `stage`·`reviewNote`가 삭제되고 `origin`은 남는다
- 기각 기록 **수정**(`editing`) 시에는 아무것도 지우지 않는다

### `selfcheck-rejection-ledger.js` — DOM

- 검토중 카드에 계기·체크박스 3개가 렌더된다 (`origin` 없으면 계기 줄이 안 뜬다)
- 체크박스 토글이 `candidates[].stage`에 반영되고 저장된다
- `✎ 메모` 모달이 열리고 `origin`·`reviewNote`를 저장한다
- 기각 카드에 계기가 남고 체크박스는 없다
- 칸 회수 모달에 `h.thesis`가 표시된다 (없으면 그 줄이 안 뜬다)
- 종목 추가 폼 리셋 후 `i-thesis`가 비어 있다

### 돌연변이 검사

새 테스트가 실제로 무는지 확인한다. 최소 두 개 — `origin` 승계를 끊고, 기각 시
삭제를 빼고 각각 FAIL이 나오는지 본다. 방법은
`docs/superpowers/browser-checklist-rejection-ledger.md`의 headless 절차를 쓴다.

## 문서 갱신

- **PRD §4.4** — 후보 파이프라인 계층에 검토 필드 3종과 `holdings.thesis` 승계를 기술
- **PRD §7** — 결정 기록 D19: 검토 필드는 작업 기억이라 잠금을 안 걸고, 기각 시
  `stage`·`reviewNote`를 버린다. 기각한 대안: 전부 보존(죽은 데이터), 기각 카드에 계속 표시(카드 비대)
- **`browser-checklist-rejection-ledger.md`** — 2단계에 검토중 카드 항목 추가

## 기각 조건 — 언제 되돌리나

PRD §9의 후보 파이프라인 점검(2029-08)에 한 줄을 얹는다. 아래 중 하나면 이 기능은
규율이 아니라 장식이다:

- 체크박스가 실제로 토글되지 않는다 (전 항목이 등록 시 상태 그대로)
- `origin`이 절반 이상 비어 있다
- `reviewNote`가 한 번도 쓰이지 않았다

되돌리기는 쉽다 — 필드가 전부 선택적이라 렌더만 걷어내면 기존 데이터가 그대로 살아 있다.
