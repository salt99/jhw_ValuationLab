# 2026-08-09 · 후보 파이프라인 (기각 원장)

**결과**: 배포됨. `71f8d61..76c1b01`, 커밋 23개.
**관련**: [SPIKE](../spike/2026-08-09-punchcard-frame.md) · [SPEC](../superpowers/specs/2026-08-09-rejection-ledger-design.md) · [PLAN](../superpowers/plans/2026-08-09-rejection-ledger.md) · PRD §4.4 · ADR D15~D17

## 무엇을

TOOL 04에 후보 파이프라인을 추가했다. 검토중 대기열 · 기각 원장 · 칸 회수 세 섹션,
14일 유예 잠금, 3년 검증 루프. PRD에 P8(칸 회계)과 '1칸' 정의표.

핵심은 **기각 판단을 3년 뒤 반증 가능하게 기록하는 것**이다. 기각 사유·당시 주가·재검토
트리거를 남기고, 3년 뒤 검증 모달이 "틀렸다면 TOOL 03의 r·N 가정을 재검토하라"고 지시한다.
이 연결이 없으면 원장은 기록일 뿐 학습 장치가 아니다.

## 어떻게

브레인스토밍 → 스펙 → 계획 → 9개 태스크. 각 태스크마다 구현자·리뷰어 서브에이전트를 붙이고,
마지막에 전체 브랜치 리뷰(opus). 총 에이전트 약 40개.

## 배운 것 — 이게 이 로그의 본론

**발견된 실질 결함 9건이 전부 계획서에서 나왔다. 구현자가 만든 결함은 0건.**
병목은 코드 작성이 아니라 설계였다. 계획이 구체적일수록 구현은 전사(轉寫)에 가까워지고,
남는 오류는 전부 계획의 오류다.

그중 둘은 계획서가 지시한 검증 절차로는 **원리적으로** 발견 불가능했다.

- `importData` 데이터 유실 — 검증 절차가 "내보내기 후 되가져오기"였는데, 같은 세션에서는
  값이 우연히 일치해 버그가 가려진다. 백업 복원 시 기각 원장이 통째로 사라지는 결함이었다.
- `rj-intro` 오염 — Task 5가 만든 모달을 Task 8이 함수 *밖에서* 덮어썼다. 태스크별 리뷰는
  서로를 볼 수 없어 전체 브랜치 리뷰에서만 드러났다.

→ 교훈: **검증 절차 자체를 설계할 때 "이 절차로 안 잡히는 것은 무엇인가"를 물어야 한다.**
→ 교훈: 태스크를 쪼개면 태스크 간 이음매가 사각지대가 된다. 전체 리뷰는 형식이 아니라 필수다.

**브라우저 검증을 끝까지 미룬 것이 최대 실책.** 서브에이전트가 브라우저를 못 열어서
22개 커밋 전부 구문 파싱과 코드 리딩으로만 확인했다. 배포 후 사람이 30초 만에 레이아웃
버그를 찾았다(`.fld` 그리드 아이템의 `min-width:auto`). 정적 분석이 구조적으로 못 보는
영역이 있다는 걸 알면서도 그 영역의 확인을 마지막까지 미뤘다.

→ 대응: `docs/superpowers/build-selfcheck.js` 를 만들어 DevTools 없이 검사가 돌아가게 했다.
   다음부터는 UI를 만드는 태스크가 끝날 때마다 이걸 돌린다.
